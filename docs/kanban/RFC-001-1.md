# Project — concluir subresource POST (entidade direta)

## Contrato de Entrada
- `POST /partners/{partnerId}/projects` com corpo JSON:
  - `name`: string não vazia (max 255)
  - `description`: string opcional (max 1000)
- `partnerId`: ID prefixado do Partner (`prt_...`) na URI, resolvido via `UriVariableTransformer`.

## Contrato de Saída
- `201 Created` com a entidade `Project` serializada no grupo `project:get`: `id` (`prj_...`), `name`, `description`, `active`, `createdAt`.
- `404 Not Found` quando o `partnerId` não existe ou o Partner foi soft-deletado.
- `GET /partners/{partnerId}/projects`, `GET /projects/{id}` e `PATCH /projects/{id}` continuam funcionando.

## Requisitos de Qualidade
- [ ] Integração: `ProjectApiTest` verde (POST/GET collection no subresource, GET/PATCH item, 404, escopo por parceiro)
- [ ] Unitário: `Project` instancia sem `Partner` e aceita `setPartner()` fluente

## Restrições Técnicas
- Declarar `provider: CreateProvider::class` no `Post` do subresource (sem isso a relação não é populada).
- Remover `$partner` do construtor de `Project`; adicionar `setPartner(Partner $partner): static` (fluente).
- Manter o `uriVariables` com `Link(fromClass: Partner::class, toProperty: 'partner')`.
- Ajustar `ProjectPostProcessor` e `ProjectRegistrar` para o fluxo de entidade direta (não instanciar `new Project($partner, ...)`).
- Seguir o padrão de `Partner` (grupos por método, sem DTOs, sem `else`, setters fluentes).
